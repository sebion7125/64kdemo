## State of work (covers turns 1–28)
The session focuses on the tree LOD system in the EZ-Tree clone at `/home/xvm/Projekte/64kDemo`. The primary goal is achieving visual consistency and smooth transitions across LOD tiers, addressing leaf color fidelity, geometry completeness, and the "LOD catastrophe" where leaves appeared incorrectly colored or invisible. Work has progressed from structural fixes to implementing per-tree coloring, resolving rendering artifacts, and rearchitecting the LOD pipeline to prevent visual popping and ensure exclusive layer rendering.

**Current Status and Implementation**
The LOD system now generates leaf cards in all tiers, with density controlled by hash-culling. Core logic uses `camPos` for distance calculations. A breakthrough resolved the color mismatch where `uAlbedoOnly` remained set to 1 after atlas capture, causing unlit raw albedo rendering. This fix ensured consistent color values between single leaves and cards [T8].

**Leaf Color and Atlas Strategy (S2)**
The implementation of S2 (Cluster atlas + per-tree color) is complete and verified.
*   **Atlas Content:** The atlas tile is a single neutral leaf cluster (9–13 leaves, 27% coverage) baked without color [T6, T8].
*   **Color Propagation:** Per-tree leaf color (`ezLeafR/G/B`) is stored in crown instance data (`CROWN_FLOATS` increased to 13) and multiplied in `crown.frag` [T6, T8].
*   **Lighting Consistency:** `crown.frag` applies two-sided diffuse and translucency lighting to match `leaf.frag`, ensuring identical light reaction [T7].
*   **Palette Tuning:** Leaf color consistency across LODs is confirmed (Δ ≤ 1 channel). The remaining visual difference is coverage, not tint. A new default palette "wald" (hue 101–130°, sat 0.65–0.88, val 0.38–0.58) was chosen to address user complaints about "autumnal" or pale leaves. The old hue lower bound of 72° (olive/yellow-green) was identified as the cause and raised to 101° [T14]. Palette is tunable via `DEMO_LEAFPAL` or `DEMO_LEAFHSV` [T14, T16].

**Geometry and Budget Adjustments**
To address "cut-off trunks" and insufficient foliage, geometry budgets and generation logic were updated [T9].
*   **Budget Increases:** `TREE_VERT_CAP` and `CROWN_CAP` were raised to prevent tree skipping. Initially set to 5.2M/3.6M, they were later lowered to 3.8M/4.0M to accommodate double buffering for worker threads [T9, T17].
*   **Branch Closure:** Non-terminal branch ends are closed using `emit_cap`, increasing scaffold density by 6.9% [T9].
*   **Sprig Cap:** `EZ_SPRIGCAP` increased from 4096 to 16,384 [T9].
*   **Card Emission:** Cards are emitted in every tier to prevent gaps during camera motion [T8].

**LOD Pipeline Rearchitecture**
The user reported severe popping and wild switching between LODs. The pipeline was rearchitected to ensure layers are mutually exclusive rather than overlapping [T27, T28].
*   **Exclusive Layers:** Crown cards are no longer a base layer under leaves. They fade in only at 0.9–1.1·R1, so near trees show individual leaves alone. Individual leaves fade out at 0.9–1.1·R1. The whole-tree billboard fades in at 0.70–0.95·R2 [T27, T28].
*   **Switch Distances:** R1/R2 thresholds adjusted to 5×/15× tree height (clamped R1 20–60 m, R2 40–120 m) based on measurements showing single leaves only cover up to ~5× height [T25].
*   **Impostor Atlas:** Procedural crown tiles were replaced by a render-to-texture impostor atlas (8×8 tiles × 128 px, 1024² RGBA). 64 buckets (4 presets × 16 forms) capture each tree's own VBO slice (skeleton + card tier) sliced over frames at 12% of frame time [T28].
*   **Billboard Fixes:** The whole-tree billboard quad now spans trunk+crown (previously crown-only, causing floating green blobs). Wind amplitude for billboard tiles is set to 0 to prevent unnatural swaying [T27, T28].
*   **Leaf Size:** Default `ezLeafScale` doubled to 2.0, increasing leaf pixels at 10m from 6639 to 14066 [T27].

**Performance and Stutter Resolution**
Tree rebuilds caused 490 ms frame-blocking (350 ms generate + 140 ms upload).
*   **Worker Thread (Plan B):** Tree generation moved to a worker thread with CPU double buffers and two VBO/VAO sets. Upload is sliced with a time budget (25% of last frame time, clamped 3–20 ms). Frame-blocking dropped to 0 ms [T17].
*   **Double Buffering:** Caps lowered to fit double buffering (~876 MB CPU total). `drawSet` flips only after the last upload slice to prevent GPU seeing half-uploaded geometry [T17].
*   **Culling Fix:** The hard 30 m cull of the old set during fades was removed to prevent popping [T25].

**Known Issues and User Feedback**
*   **Reed Pass:** A new reed pass (`src/reed_cpu.c`) was implemented but is currently paused. The user reported reeds appearing in different locations than the old grass-based reeds and fading incorrectly. Reed work is on hold until tree LOD is approved [T20, T21, T26, T28].
*   **Shadows:** Shadow issues remain unresolved and are deferred by the user as a larger separate task [T21, T25].
*   **Measurement Validity:** VM screenshots and FPS measurements are deemed unreliable for visual judgment due to non-deterministic timing and low frame rates. The assistant now presents builds for the user to test on the host [T22, T28].
*   **Uncommitted Changes:** Recent LOD rearchitecture changes (exclusive layers, impostor atlas) are built but not yet committed. Reed corrections are also uncommitted [T26, T28].

**Decisions and Rationale**
*   **Color Source:** Leaf color lives exclusively in instance data; the atlas remains color-neutral [T7].
*   **Measurement Protocol:** Tests must use `DEMO_FREEZE` and isolate the tree (`DEMO_NOTERRAIN=1 DEMO_GRASSMD=0 DEMO_REEDPASS=0`) to avoid contamination from grass/reeds [T14, T26].
*   **Budget Strategy:** Increase buffer caps rather than skip trees to ensure full rendering [T9].
*   **LOD Strategy:** Layers must be mutually exclusive with crossfade bands. Cards are the mid-range layer, leaves are near-range details, billboards are far-range. This prevents the "leaf over card" artifact [T27, T28].
*   **Impostor Strategy:** Use per-type bucket impostors captured from the card tier to save fill rate and vertex work [T28].
